# concept.md — TROT

**Transparent Rust ONNX Trainer** · repo: `trot-livive-net`

---

## The Idea

TROT is a neural network you can read.

A small multilayer perceptron, written from scratch in Rust, compiled to WebAssembly, trained live in your browser, and exported as an ONNX file. Every weight, every gradient, every multiplication in the forward pass is rendered on the page as a number you can point at. Nothing is hidden behind a library call.

The model is deliberately tiny — one hidden layer, a fixed 50-token vocabulary, eight hidden units. The hidden activation is selectable (`tanh`, `relu`, or `leaky_relu`), so the same page shows how the choice changes the forward pass and its derivative. Small enough that a person can trace a single prediction by hand and confirm the arithmetic themselves. That is the entire point. Accuracy is not the deliverable. Transparency is.

## Why It Exists

There is a gap between "here is how a neural network works" (diagrams, arrows, conceptual animations) and "here is a neural network" (a pip-install, a checkpoint download, a `model.predict()` call). Between those two lies the thing that actually matters: **the code**. The forward pass. The backward pass. The weight update. The artifact that comes out the other side.

TROT fills that gap. It is a real model — real weights, real gradients, real training — with none of the usual opacity. The source is the documentation. The page is the debugger.

## What the Learner Does

1. **Trains.** Clicks a button. Watches the weight table update cell by cell and the loss curve descend. Sees train accuracy and test accuracy pull apart, and learns what that gap means. The activation and an optional L2 penalty are live controls, with the penalty and its effect on the gradients shown explicitly.
2. **Inspects the data.** Opens the data view and reads the generator grammar that produced the training corpus. The data is not a mystery blob; it is `f(seed, size)` over a template grammar they can read in one sitting. Seed and corpus size are visible controls. Label noise is explicit rather than hidden: default 0%, an 8% preset, balanced flips across both classes, and a badge on every flipped row.
3. **Reads the gradients.** Opens the gradient view after a step. Every `dW1`, `db1`, `dW2`, and `db2` cell is rendered from the last minibatch, including the `lambda*W` term when L2 is on. Hovering or focusing a cell shows the weight, its gradient, and the next-step projection `theta - lr*dtheta`.
4. **Traces a prediction.** Types a sentence. Follows it token by token through `W1`, into the hidden layer, through the selected activation, through `W2`, out of the sigmoid — every intermediate number printed on the page, every step exact.
5. **Exports.** Clicks a button. Gets an `.onnx` file. Opens it in Netron and sees the graph and initializers named exactly as they were in the source. Loads it in a standard runtime and gets the same predictions.

## What Makes It Different

Three commitments, in order of importance:

**The model is the code.** Not a wrapper around a library. The forward pass and backward pass are hand-written Rust functions with index comments. If you can read a `for` loop, you can read the model. The hidden activation is a value in the source, not a hidden library setting, and both the forward value and its derivative are rendered.

**The data is the code.** The training corpus is generated by a seeded template grammar that lives in the source. No committed JSON blob, no scraped dataset. The vocabulary is fixed at exactly 50 tokens so the weight table stays readable as a grid. The corpus is deterministic in seed and size; both are visible controls, and changing either produces a different corpus. Label noise is never silent corruption: it is an explicit rate (0% by default, with an 8% preset), balanced across classes, and marked row by row.

**The artifact is inspectable too.** The ONNX export is not a black box at the end of the pipeline. The initializers are named after the source struct fields. The graph is four nodes, with the activation node matching the selected activation. It opens in Netron and reads like the Rust; the byte-level encoder is documented in `onnx_details.md`.

## Scope

**It is:** a teaching tool. A reference implementation. A demonstration that "browser-first" and "fully inspectable" are not in tension.

**It is not:** a framework, a benchmark, a transformer, a general ML library, a hosted service, or a component of some larger application. It stands alone.

Binary sentiment over short business-review snippets. Minibatch SGD. One hidden layer. That is the whole model. Anything that would make it harder to trace by hand is out of scope.

## The Test of Success

A person with a browser and no Rust toolchain can open the page, train the model, trace a prediction number by number, export the ONNX file, load it in a standard runtime, and get the same answer — and at no point in that sequence does anything happen that they cannot explain.

When that works, the question "where is the model code?" has an answer: it's the repository, it's the page, and it's the `.onnx` file. All three.
